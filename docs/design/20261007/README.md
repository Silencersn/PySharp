## 最重要的发现

两处经双解释器比对确认的正确性缺陷（均附最小复现与局部修复建议）：

1. 二元运算分派用语义相等判定「两操作数类型相同」，元类的 `__eq__` 可以
   劫持 `+` `-` 等运算的求值顺序，其异常也会传染运算本身；CPython 为指针
   比较，不受影响。该判定同时是算术指令热路径上的固定协议调用开销。
2. `__bases__` 重赋值后类型只重算继承槽，**自有类体槽全部丢失**
   （定义了 `__add__` 的类改基类后 `B() + 1` 报 TypeError，CPython 正常）。
   提交段缺一次已存在的 `FixupAllSlots` 调用。

一处结构性风险：静态类型反射槽的自动合成对非交换运算默认开启，其正确性
依赖「前向槽对 other 有类型守卫」这一未成文约定（`set` 因守卫而幸免，
dict 视图已踩雷一次并以手写 `RSub` 补偿）。建议规则成文并配分析器警告。
