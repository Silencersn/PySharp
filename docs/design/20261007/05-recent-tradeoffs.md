# 近期版本的设计权衡评审

评审基线：master 分支 88c2b740。范围：近期以对齐 CPython 3.14 为目标的合并
（PR #517 描述符化与 `__slots__`、#518 sys 注册表、#521 threading、
#522 `__qualname__`、#523-#524 str 性能与码点、#566 反射槽修正、#567 dict
合并与视图集合运算），评估这些变更引入或暴露的设计选择。机制细节引用前四篇，
本篇只做权衡层面的裁决与路线建议。

## PR #566：合成反射槽的双重交换修正

该 PR 建立的「槽字段与属性 wrapper 是两个不同委托」模型（分发层已交换、
属性层翻转）经本评审逐条与 CPython 对照验证：槽字段镜像 `SLOT1BIN` 的反射
分支调用序，wrapper 镜像 `wrap_binaryfunc_r`，继承槽跳过镜像
`slot_inherited`，注释与 CPython 行号的对应准确。**模型本身是对的**，它与
CPython 的分歧（独立 `R*` 槽 vs 无反射槽字段）由强类型 self 桥的结构约束
决定，属于合理的移植决策。

遗留问题是该模型把一条安全前提留在了暗处：非交换运算的合成反射依赖前向槽
对 other 的类型守卫（详见
[02-slots-and-dispatch.md](./02-slots-and-dispatch.md) 的分析），而这条前提
既无文档也无诊断。#567 在 dict 视图上靠手写 `RSub` 补偿正是前提失守的实例。
裁决：**保留模型，成文前提**——按 02 篇建议把「other 守卫 → 是否可依赖合成」
的判定规则写进贡献者文档，并考虑 `PYSPI` 分析器警告。

## PR #567：dict 合并与视图集合运算

实现面干净（见
[04-builtin-type-patterns.md](./04-builtin-type-patterns.md) 的样本分析），
两处决策值得在更长时间尺度上复盘：

- `ViewLeftDifference` 把「`binary_op1` 第三步原序语义」编码为 dict 视图的
  私有实现。这是当下正确的最小改动，但它是通用问题的第 N 个点状补丁
  （`PyOperators` 分发层与 CPython 第三步的语义差对所有静态类型存在）。
  若采纳 02 篇的分析器警告路线，此类手写实现会从「踩雷后的修复」前移为
  「实现时的显式选择」。
- items 视图 `^` 的 `dictitems_xor` 特化（按 key 配对、值相等剔除、不可哈希
  抵消对不进 set）是对 CPython 特化算法的忠实转置，且用
  `PyComparer.Eq` 的 identity 快路径对应了 `RichCompareBool`。该特化只在
  「两侧都是 items 视图」时启用，否则回落通用路径——与 CPython
  `dictviews_xor` 的分派一致，无过度设计。

## PR #517：`__class__`/`__dict__` 描述符化与 `__slots__`

该 PR 把 `__class__` 收敛为 getset 描述符、实现 `__slots__` 声明管线，语义面
完成度高（`_Py_Mangle`、`may_add_dict`、`type_new_slots_bases`、布局冲突检查
逐一对齐，见 `PyTypeObjectOfT.cs` 的 `TryResolveSlots` 注释链）。架构层面的
两个遗留已在 [01-object-model.md](./01-object-model.md) 记录：

- `PySlotsObject` 哨兵把「无实例字典」编码为 CLR 布局，语义正确，但成员存储
  后端仍是条件弱表——`__slots__` 在性能上劣于普通实例字典，与使用者的
  CPython 直觉相反。裁决：短期文档化该差异；中期若做实例存储分化，
  `__slots__` 成员可迁往与 `PyObjectManagedDict` 同形的实例字段通道
  （描述符种类已区分访问路径，迁移面收敛）。
- `IsImmutable` 同时承载「无实例字典」与字面意义的「不可变」。建议改名或
  补充注释，防止未来消费者拿它推断值可变性。

## PR #518（sys）与 #521（threading）：模块面扩张

这两个 PR 与对象模型的交互浅，架构影响主要在模块系统侧，不在本组文档范围。
一点记录：sys PR 过程中出现的 `SimpleNamespace` 按 `namespace_init` 拆分构造、
`sys.modules` 短路收窄等修正，显示「先宽后窄」的落地节奏有效，未发现需要
复议的结构决策。

## PR #523-#524（str 码点快路径与代理项）

字符串侧的性能工作把索引/切片/搜索改走码点快路径、拼接保留孤立代理项为
独立码点。这类优化与对象模型正交，且带了充分的回归语料。不涉及待斟酌的
架构面。

## 汇总：待办清单

按优先级合并前四篇的结论（细节与证据在各篇）：

| 优先级 | 事项 | 类别 | 出处 |
| --- | --- | --- | --- |
| P1 | 分派层类型相等改引用比较（元类 `__eq__` 劫持 + 热路径开销） | 正确性 | 02 篇「缺陷一」 |
| P1 | `RebuildMro` 后对子树跑 `FixupAllSlots`（`__bases__` 重赋值丢自有槽） | 正确性 | 02 篇「缺陷二」 |
| P2 | 非交换二元槽的反射合成约定成文 + `PYSPI` 警告 | 可维护性 | 02/03 篇 |
| P2 | `__slots__` 存储后端差异文档化（或实例字段化） | 性能语义 | 01 篇 |
| P3 | `type.__new__` 阶段拆分与 `__class_getitem__` 注入段提取 | 可维护性 | 04 篇 |
| P3 | `PyOperators` 槽表收敛为单张数据表 | 可维护性 | 02 篇 |
| P3 | `IsImmutable` 改名/注释；生成器 `AddSource` 去重；构造函数合并；`GetAttrOrMethod` 双份标注 | 卫生 | 01/03/04 篇 |

两个 P1 均有局部修复路径且已附最小复现，适合各自开 issue 跟进；修复时
建议把复现脚本转成 `test_pyfiles` 回归语料（进程内 + CPython 差分双引擎），
沿用仓库既有的验证闭环。

## 结语

近期的 CPython 对齐工作总体质量高：决策有注释溯源、验证有差分回归、扩张
有先例可循。暴露出的系统性主题只有一个——**模型的隐含前提积累速度快于
成文速度**（反射合成的守卫前提、`FillNullWith` 引用拷贝前提、`IsImmutable`
的双重语义）。这些前提在代码里都以注释形式存在，但缺少面向贡献者的集中
陈述与机械防护。把「注释里的不变量」提升为「文档中的规则 + 分析器中的
警告」，是当前投入产出比最高的一项架构投资。
